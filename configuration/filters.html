Filters

filter: on a service in services.yaml hides its card while an expression is true; on one of its widgets it hides that widget. The expression reads the attributes its widgets and status checks publish: public values a widget declares for this (the Filter attributes table on each widget’s page lists them), apart from the blocks it shows. For example, a Shelly device that only appears while a firmware update is waiting:

- Devices:
    - Shelly Bureau:
        href: http://shelly-bureau.lan
        filter: widget.update == false          # hidden while there is no update
        widget:
          type: shelly
          url: http://shelly-bureau.lan
          password: "{{DASHBOARD_VAR_SHELLY_PASSWORD}}"

The expression

  • An attribute: widget.<name> reads the attributes of all the service’s widgets together, so it works the same with one widget or several. When two widgets publish the same name, the first one on the card counts. To read one widget only: widgets[1].<name> (by position, from 0) or widgets.shelly.<name> (the first widget of that type).
  • A status check: container.<name>, ping.<name> and siteMonitor.<name> read the service’s container:, ping: or siteMonitor: check rather than a widget on the card (see Container health and Devices that do not answer).
  • A value: true, false, null, a number, 'text' or "text".
  • Comparing: ==, !=, <, <=, >, >= (< and > only between numbers).
  • Combining: && (and), || (or), ! (not), and parentheses: filter: widget.update == false && widget.queued == 0.

A bare attribute is true while its value is: filter: ping.attention is the same as filter: ping.attention == true, and filter: "!ping.attention" the same as filter: ping.attention == false (in quotes: YAML reads a leading ! as a tag). The one difference: an attribute nobody sent is null, which ! counts as false and == false does not.

Attributes of the status checks

A service’s status checks publish these, whatever widgets it has. The attributes of a widget on the card differ per widget: see its page under Filter attributes. Most widgets also publish attention there, true while the card marks something as needing attention.

container.<name>, the service’s container: (Docker):

Attribute Type Value
attention boolean true while the container is unhealthy (its Docker healthcheck), stopped or not found
status text up, warn (running but unhealthy, or a Swarm service with too few tasks) or down

ping.<name>, the service’s ping::

Attribute Type Value
attention boolean true while the host does not answer
status text up or down
latency number the answer time in ms; null without an answer

siteMonitor.<name>, the service’s siteMonitor: (HTTP):

Attribute Type Value
attention boolean true while it is not up: 5xx, another 4xx or no connection (2xx, 3xx and 401/403, a login in front of it, are up)
status text up, warn (another 4xx) or down
code number the HTTP status code, such as 200; null without a connection
latency number the answer time in ms; null without a connection

Before a check has answered every attribute is null, and the card stays hidden; when the check itself fails, the card is shown.

While it waits, and when it fails

An attribute no widget sent counts as null, so widget.update == false is not true before the widget knows. Until the widgets the filter reads have answered, the card stays hidden; when one of them fails, the card is shown, so a broken service never disappears quietly. A group whose cards are all hidden is hidden too, and a hidden card is no search hit. While filters hide cards, the footer says how many (“3 hidden”); a click shows them, dimmed, until the next click.

Container health

Whether a service is healthy is decided by its container, not by a widget, so container.<name> reads the attributes of the service’s container: check: attention is true while the container is unhealthy (its Docker healthcheck), stopped or not found; a running container without a healthcheck is fine. To show a service only while something is wrong with it:

- Media:
    - Plex:
        href: http://plex.lan:32400
        container: plex
        filter: container.attention == false    # hidden while all is well; "!container.attention" works too

To tell unhealthy from stopped, container.status is warn for the one and down for the other. Discovered Docker services have container: already, so the label dashboard.filter=container.attention == false works there.

Devices that do not answer

ping.<name> reads the service’s ping: check: attention is true while the host does not answer. siteMonitor.<name> reads the HTTP check the same way: attention is true while it is not up. To hide a device while it is off:

- Living room:
    - Sonos:
        ping: sonos.lan
        filter: ping.attention                 # hidden while it does not answer

filter: ping.attention == false (or filter: "!ping.attention") does the opposite: the card only shows while the device is down.

A widget’s filter

filter: on one entry of widgets: hides that widget instead of the card, in the same language and reading the same attributes. For example a button that only shows while there is something to update:

- Docker:
    - Wud:
        widgets:
          - type: whatsupdocker
            url: http://wud:3000
          - type: button
            text: Update containers
            filter: widgets.whatsupdocker.updates == 0   # hidden while there is nothing to update
            timeout: 900
            command: >-
              curl -fsS http://wud:3000/api/containers
              | jq -r '.[] | select(.updateAvailable) | .id'
              | while read -r id; do
                  curl -fsS -X POST "http://wud:3000/api/containers/$id/triggers/docker/update" >/dev/null || exit 1;
                done

The widget behaves as a filtered card: hidden until the widgets its filter reads have answered, and shown when one of them fails. A hidden widget keeps refreshing, since other filters may read it. The footer’s “hidden” is about whole cards: it does not count a hidden widget. It works on service widgets only (a header widget such as search keeps its own options), and a widget that has an option named filter itself keeps that option.

Discovered services

Discovered services take filters too: as the Docker label dashboard.filter (see Docker), or as the Kubernetes annotation getdashboard.dev/filter on an Ingress (see Kubernetes; getdashboard.dev/ is the annotations’ prefix, not a web address). A widget’s filter is dashboard.widgets[1].filter:

# compose.yaml: Compose's list form keeps the quotes and && of an expression simple
labels:
  - dashboard.name=Shelly Bureau
  - dashboard.filter=widget.update == false

# an Ingress
metadata:
  annotations:
    getdashboard.dev/enabled: "true"
    getdashboard.dev/filter: widget.update == false

Recipes

A filter hides a card while all is well, so the dashboard shows what needs a look:

- Media:
    - Radarr:                                   # only while it marks something, such as a blocked import
        href: http://radarr.lan:7878
        filter: widget.attention == false       # or "!widget.attention"
        widget: { type: radarr, url: http://radarr.lan:7878, key: "{{DASHBOARD_VAR_RADARR_KEY}}" }
    - Updates:                                  # only while a container has an update
        filter: widget.updates == 0
        widget: { type: whatsupdocker, url: http://wud.lan:3000 }
- Infrastructure:
    - Proxmox:                                  # only while a VM is stopped
        href: https://pve.lan:8006
        filter: widget.vmsStopped == 0
        widget: { type: proxmox, url: https://pve.lan:8006, username: "{{DASHBOARD_VAR_PVE_USER}}", password: "{{DASHBOARD_VAR_PVE_TOKEN}}" }
    - Speedtest:                                # only while the last test was slower than 100 Mbit/s
        filter: widget.download > 100
        widget: { type: speedtest, url: http://speedtest.lan }
    - Uptime Kuma:                              # only while a monitor is down
        filter: widget.down == 0
        widget: { type: uptimekuma, url: http://kuma.lan:3001, slug: home }
    - Plex:                                     # only while its container is unhealthy or stopped
        container: plex
        filter: container.attention == false    # or "!container.attention"
    - NAS:                                      # only while it does not answer
        ping: nas.lan
        filter: ping.attention == false         # or "!ping.attention"

The attributes each widget publishes are on its page under Filter attributes.

Mistakes

A mistake in the expression (widget.update false), a widget that is not on the service (widgets.radarr.queued on a Shelly), container.attention without container: or a secret in it are config errors; the service (or widget) is then shown unfiltered. An attribute the widget does not publish is a warning. The filter goes to the browser, so it cannot hold a {{DASHBOARD_VAR_*}} value.
